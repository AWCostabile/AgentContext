# From 0.4.0

What changes for an instance deployed at `v0.4.0`, and what to do by hand.

## The short version

1. Run the update with the **new** release's `init.sh` (the old one cannot read the new layout):

   ```
   bash AgentContext-<version>/init.sh --update --target <path> --ref <tag>
   ```

2. Read the report. Every `moved` line is done; every `kept` line is yours to finish (below).
3. Run `bash common/scripts/cure.sh` from the instance root until it says 0 fails, then commit.

## What moved

The core files the template rolls forward now sit in one directory, `common/`, so the root
shows the trees and little else.

| Was | Is |
| --- | --- |
| `scripts/` | `common/scripts/` |
| `rules/` | `common/rules/` |
| `templates/` | `common/templates/` |
| `HYGIENE.md` | `common/HYGIENE.md` |
| `.conf.example` | `common/.conf.example` |
| `.agentcontext` (the manifest) | `common/.agentcontext` |

The scripts now run as `bash common/scripts/<name>.sh`, still from the instance root.

With the Claude Code adapter, its three process files leave the root and two agents are renamed:

| Was | Is |
| --- | --- |
| `KICKOFF.md`, `WORKER.md`, `CLOSEOUT.md` | `.claude/process/` |
| `.claude/agents/brainiac.md` | `.claude/agents/historian.md` |
| `.claude/agents/implementer-deep.md` | `.claude/agents/principal.md` |

A habit or a note that names an agent by its old name (`brainiac`, `implementer-deep`) should
use the new one.

With the constitution copied in, its code-standards form moves beside the kickoff template:
`constitution/process/code-standards.template.md` becomes `constitution/process/templates/code-standards.md`.
The update leaves it (no 0.4.0 manifest records the constitution), and the `--adopt constitution`
run below reports the new path `missing`: move your copy there, or leave it absent if you retired
the form, and point the two articles that link it (`article.rigour.md`, `article.wave-ground-rules.md`) at the new path.

## What the update does on its own

- A file you never edited is **moved**: written at its new path, its old path removed, and any
  directory that leaves empty removed too. This is the only thing the deployer ever deletes.
- A file you deleted is simply added at its new path.
- The manifest is rewritten at `common/.agentcontext`, and the old one at the root removed.

## What is left to you

- **`kept <old> (changed locally; moved to <new>)`** — you edited this file, so it stays at its
  old path, and the release's copy is written at the new one. Bring your change across into the
  new file, then delete the old one (and its directory, when that leaves it empty). The old path
  is no longer in the manifest, so later updates will not mention it again.
- **`kept AGENTS.md (changed locally)`** or **`kept README.md (changed locally)`** — your copy
  still names the old paths. The report's `run bash common/scripts/cure.sh` line says so; the
  linter lists each dead link. Respell them by the tables above (`./rules/` becomes
  `./common/rules/`, `bash scripts/` becomes `bash common/scripts/`, and so on), or take the
  release's copy at `common/` — compare with the template's `blueprint/AGENTS.md` — and re-apply
  your own lines.
- **A process file kept at the root** (an edited `KICKOFF.md`, say) — the adapter's hooks now
  read `.claude/process/`, so your edits there take effect only once moved across.

## What does not happen

- Nothing under `public/`, `private/`, `constitution/` or `graphs/` moves, and `.conf`,
  `.gitignore`, `.gitattributes` and the workspace file are not touched.
- A module you copied in by hand at `v0.4.0` (`modules/<name>/`, or the constitution at
  `constitution/`) is not in the manifest, so the update leaves it where it is.

## Bringing a hand-copied module under the manifest

After the update, run once per module you copied in, with the same release's `init.sh`:

```
bash AgentContext-<version>/init.sh --adopt <module> --target <path>
```

A script module still at `modules/<name>/` is moved to `common/modules/<name>/` file by file, as
the update moved the core: a file that matches the release moves, and one you edited stays at its
old path beside the release's copy, reported `kept`, for you to bring across. The constitution,
already at `constitution/`, is recorded with nothing copied, and each file is reported `matches`
or `differs`; a leaf you pruned, amended or marked adopted differs, and every later update keeps
it. Either way the module gains a `module=` line in `common/.agentcontext`, and from then on the
update refreshes it.
