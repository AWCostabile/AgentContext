# Winchbook design: code standards

_source:_ constitution/history/rulings/rulings.commits-and-pull-requests.md CP1–CP11 2026-11-04
_reviewed:_ 2026-11-04

Winchbook's rules for its own history and review, copied from the constitution's code-standards
template when the constitution was adopted. The worker's ground rules and the close-out check
read these values from here.

## Commit subjects

- A subject is `<prefix>: <subject>`, the prefix exactly one of:
  `chore` `docs` `feat` `fix` `refactor` `style` `test`. No scoped form (`feat(queue):`).
- A subject reads as a product update: no item numbers, no review rounds.
- Trailers refused: tool-attribution co-author lines. The close-out check fails a refused
  trailer as a hard hit.
- Detail belongs in the body; the change log reads the pull-request title and every subject.

## Branches

- Branch names: `feature/<PascalCaseName>`, `fix/<PascalCaseName>` or `docs/<PascalCaseName>`
  off `main`.
- Agents never push; the owner raises every pull request.

## Pull requests

- Title: a human-readable heading, such as `Feature | Day Sheet`; it becomes the change-log
  heading.
- Body: an impersonal record of what the change achieves, its proof and what it leaves out; no
  personal names, no first person. About 20–30 lines.
- The body is filed before the pull request is raised, its first line naming the branch.
- Merge strategy: merge commit, made by the change-log workflow, which squashes the branch and
  rewrites `main`; after a merge every clone re-syncs with a fetch and a hard reset.

## The change log

- `CHANGE_LOG.md` is generated by the post-merge workflow in Winchbook's own repository after every merge and never edited by
  hand.
- Each entry is made from the merge title as the heading and each branch commit subject as a
  bullet.
- A fix to unreleased work is folded into the commit it fixes before the pull request, so it never
  becomes a bullet.

## Gates

| Gate | Proves | Command |
| --- | --- | --- |
| the test suite | every package's tests pass, the flight log's included | `go test ./...` |
| the format check | every file is as the formatter writes it | `gofmt -l .` prints nothing |
| the vet pass | no suspicious construct the compiler lets through | `go vet ./...` |

## The review loop

- Before a pull request is raised, a reviewing agent reads the diff: adopted.
- Round cap: `ORCH_REVIEW_ROUNDS=1` in `.conf`; `0` disables the loop.
- Finding cap: 5; findings graded blocking or consider; style the formatter owns is never a
  finding.
- The rule catalog: not yet built.

## Not adopted

- Stacked branches across several pieces of work: Winchbook's changes are small enough to land
  one at a time.
