# Reference

Lookup facts about the tooling this tree received, kept beside it so an agent can answer why a
deployer run refused or what the template last did here. [HYGIENE.md](../HYGIENE.md) is the
reference for every check, smell and exit code; the deployer keeps the rest of this branch.

## Contents

| File | Purpose |
| ---- | ------- |
| [The deployer's refusals](./refusals.md) | every message the deployer refuses with, what it means and what to do |
| `updates.md` | the ledger: one line per deployer run that changed this tree; created by the first such run |
| `migrations/` | the migration guides that applied to this tree, each copied in by the update that named it; created with the first |

## The ledger

`updates.md` is the one file the deployer appends to rather than replaces, and only the deployer
writes it. An update that changed something (a file moved, replaced, kept, added or removed
upstream, or the release itself) appends

```
- YYYY-MM-DD — update <from> → <to>: N moved, N replaced, N kept, N added, N removed-upstream
```

with `<from>` and `<to>` the releases before and after and the counts its report ended with. An
update that changed nothing, and every dry run, append nothing. Adopting a module appends

```
- YYYY-MM-DD — adopt <module>: N file(s)
```

with N the files written, 0 when the module was already in place and only recorded.

`migrations/<version>.md` is the guide of the release `<version>` leaves, copied unchanged from the
template when an update kept a file and named the guide: what that release left for the user to
finish by hand. Neither the ledger nor the guides are in the manifest: an update never replaces,
reports or removes them.
